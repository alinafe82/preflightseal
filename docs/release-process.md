# Release Process

This is the maintainer runbook for the public `preflightseal` npm package.

## Release Authority

- Official repository: `alinafe82/preflightseal`
- Official package: `preflightseal`
- npm package access: public
- npm publishing path: trusted publishing from GitHub Actions
- Trusted publisher: `.github/workflows/release.yml`
- GitHub environment: `npm-publish`

Do not add a long-lived `NPM_TOKEN` GitHub secret for routine releases. The
release workflow uses npm trusted publishing with GitHub OIDC and
`publishConfig.provenance` enabled in `package.json`.

`preflightseal@0.1.0` was bootstrapped with a local maintainer publish before
trusted publishing was configured. Do not create a publishing GitHub release for
`v0.1.0`; the next routine release must bump `package.json` first.

## Routine Release

1. Update `package.json`, `package-lock.json`, and `CHANGELOG.md` in a pull
   request.
2. Run the local release gate from a clean checkout:

   ```sh
   npm ci --ignore-scripts
   npm run build
   npm run check
   npm test
   npm run coverage
   npm run schemas:check
   npm run dogfood:fixtures
   npm run package:audit
   npm run secret:scan
   npm run release:contamination-check
   npm audit --ignore-scripts
   npm publish --dry-run --access public --provenance=false
   ```

   The local dry-run disables provenance because npm provenance is generated by
   the trusted GitHub Actions publisher, not by a local shell.

3. Verify the package installs and the bin runs from the packed artifact:

   ```sh
   VERSION="$(node -p "JSON.parse(require('fs').readFileSync('package.json', 'utf8')).version")"
   TMP_DIR="$(mktemp -d)"
   npm pack --pack-destination "$TMP_DIR"
   npm install --ignore-scripts "$TMP_DIR/preflightseal-$VERSION.tgz" --prefix "$TMP_DIR/project"
   "$TMP_DIR/project/node_modules/.bin/preflightseal" --help
   ```

4. Merge only after required GitHub checks pass on the PR.
5. Create a GitHub release from the merged `main` commit with tag `v$VERSION`.
   Publishing the GitHub release triggers `.github/workflows/release.yml`.
6. Wait for the release workflow to finish successfully.

## Post-Release Verification

After the release workflow publishes, verify registry metadata and a fresh
registry install:

```sh
VERSION="$(node -p "JSON.parse(require('fs').readFileSync('package.json', 'utf8')).version")"
npm view "preflightseal@$VERSION" version repository dist.integrity dist.tarball bin --json

TMP_DIR="$(mktemp -d)"
npm install --ignore-scripts "preflightseal@$VERSION" --prefix "$TMP_DIR/project"
"$TMP_DIR/project/node_modules/.bin/preflightseal" --help
```

Also confirm the GitHub release workflow concluded successfully:

```sh
gh run list --workflow release.yml --limit 5
```

## Trusted Publishing Maintenance

Use npm CLI `11.15.0` or newer for `npm trust`. If the globally installed npm
does not include the command, run it temporarily:

```sh
npm exec --yes --package=npm@11.15.0 -- npm trust list preflightseal
```

The expected trusted publisher is:

```text
type: github
repository: alinafe82/preflightseal
file: release.yml
environment: npm-publish
permissions: publish, stage publish
```

If the trust relationship has to be recreated, use a maintainer npm session
protected by two-factor authentication:

```sh
npm exec --yes --package=npm@11.15.0 -- npm trust github preflightseal \
  --repo alinafe82/preflightseal \
  --file release.yml \
  --env npm-publish \
  --allow-publish \
  --allow-stage-publish \
  --yes
```

## Bootstrap Or Incident Publish

Local token publishing is only for bootstrapping the package name or recovering
from a trusted-publishing outage. Keep the token outside the repository, restrict
the token file to owner-only permissions, and use a temporary npm config that is
deleted when the command exits.

```sh
chmod 600 /path/to/npm-token
TOKEN="$(tr -d '\r\n' < /path/to/npm-token)"
TMP_NPMRC="$(mktemp)"
trap 'rm -f "$TMP_NPMRC"' EXIT
chmod 600 "$TMP_NPMRC"
printf '%s\n' "//registry.npmjs.org/:_authToken=${TOKEN}" > "$TMP_NPMRC"
NPM_CONFIG_USERCONFIG="$TMP_NPMRC" npm publish --access public --provenance=false
```

Never commit `.npmrc`, npm tokens, recovery codes, or one-time passwords.
